# Session 4 exercises: production deploy

In this session the main exercise is the deploy itself: you own the cloud console and the
server. Follow [docs/deploy.md](../deploy.md) and write down anything that did not match the
runbook, so it can be corrected.

## 1. Deploy to the server yourself

**Task.** Complete sections 1 to 6 of the runbook.

**Check.**

```bash
kubectl -n plaza get pods,certificate
curl -s "https://<host>/api/v1/products?q=cafe" | head -c 300
curl -sI "http://<host>/" | head -3
```

Expected: three pods `Running`, `plaza-tls` with `READY True`, JSON from the API and a `301`
to `https://`.

## 2. Follow one certificate request

Do this during the first deploy with the staging issuer (runbook section 6), in a second SSH
session:

```bash
kubectl -n plaza get certificate,certificaterequest,order,challenge
kubectl -n plaza get ingress
```

Answer:

1. Which objects appear and disappear while the certificate is being issued?
2. A second Ingress shows up for a few seconds. Who created it and what path does it serve?
3. Where does the certificate end up, and who reads it from there?
4. Why does Let's Encrypt need port 80 if the site only serves HTTPS?

## 3. Prove which image variant runs where

1. On the server: `kubectl get nodes -o wide` and `uname -m`. What is the CPU architecture?
2. On your laptop:

   ```bash
   docker buildx imagetools inspect ghcr.io/anthonygonzalez1/plaza-store-api:latest
   ```

   How many platforms does the tag contain? How does the server choose one?
3. In `services/store-api/Dockerfile`, why does the build stage have
   `--platform=$BUILDPLATFORM` and the runtime stage does not? What would happen to the CI
   build time without it?

## 4. Release and roll back

1. Change something visible in the web app (for example the page title) through a branch and
   a pull request. After the merge, deploy it with section 7 of the runbook.
2. While `helm upgrade` runs, watch `kubectl -n plaza get pods -w` in another session. In
   what order are pods created and stopped? Was the site ever down?
3. Roll back with section 8 and confirm that the old title is back.
4. Why is a rollback of the application not enough if the release included a database
   migration that dropped a column?
